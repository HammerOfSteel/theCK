# Phase 13 — Ren'Py Integration (Adapter)

> *Goal: The single, thin layer that knows about **both** Ren'Py and the procgen engine. It reads
> `content/amelia/*`, calls `engine/procgen`, and writes assets into `game/images/…`, updating
> `layered_images.rpy` references. Nothing else in the codebase touches both sides.*
> Depends on Phases 11 and/or 12 producing usable output.

---

## 13.1 The adapter
- [ ] **Create the integration script** — A build-time tool (NOT shipped runtime code) that:
      loads Amelia content → invokes engine → writes PNG/atlas/layer bundles into `game/images/`
- [ ] **Keep it thin** — All generation logic stays in `engine/`; all data stays in `content/`. The adapter
      only orchestrates and file-places. If it grows algorithms, push them down into the engine.
- [ ] **Map to existing asset names** — Output filenames must match what scripts already reference
      (`placeholders.rpy`, `layered_images.rpy`, `prompts/` naming) so swapping art needs **no script edits**
- [ ] **`layeredimage` wiring** — Generate/update `layered_images.rpy` blocks to point at produced layers
      (or generate a companion `.rpy` the game includes)

## 13.2 Swap-in strategy
- [ ] **One category at a time** — Replace placeholders per category (e.g. Cornwall backgrounds first),
      verify in-engine, then proceed — mirrors the Phase 14 art workflow
- [ ] **Placeholder parity** — Any asset the engine doesn't yet produce keeps its placeholder; no missing-file
      errors at any point
- [ ] **Regeneration is idempotent** — Re-running the adapter reproduces identical assets (engine determinism)
      and doesn't dirty unrelated files

## 13.3 Validation
- [ ] **End-to-end proof** — At least one full asset category generated by the engine and running in-game with
      **zero engine change** — only Amelia content data (this is the track's exit criterion)
- [ ] **Visual QA in-engine** — Generated assets look correct at runtime (resolution, anchors, expressions,
      phase colour) across a real playthrough
- [ ] **Build-size check** — Generated assets don't blow up the build; atlas/compression sane
- [ ] **Fallback documented** — If procgen output isn't final-quality for some category, that category falls
      back to Phase 14 manual/AI art cleanly

## 13.4 Feed forward
- [ ] **Hand off to Phase 14** — Whatever the engine produces well becomes the "done" source for that category
      in `03_art/phase_14_art_generation.md`; the rest is produced manually there

---

**Exit criteria:** Amelia consumes the procgen engine solely through content data + this adapter; at least one
asset category ships engine-generated; and removing Amelia would leave `engine/procgen` fully intact and usable.
